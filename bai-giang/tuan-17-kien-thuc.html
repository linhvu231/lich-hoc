1. DHCP: DORA từng bước

DHCP (Dynamic Host Configuration Protocol): cấp IP, mask, gateway, DNS… tự động. UDP 67 (server), 68 (client).

BướcAi gửiIP nguồn → đíchBroadcast hay unicastNội dung
DiscoverClient0.0.0.0 → 255.255.255.255Broadcast"Có DHCP server nào không? MAC tôi là …"
OfferServerServer → IP đề nghị (hoặc broadcast)Unicast hoặc broadcast (tùy cờ broadcast của client)"Anh dùng 192.168.10.25 nhé, gateway .1, DNS …, thuê 8 ngày"
RequestClient0.0.0.0 → 255.255.255.255Broadcast"Tôi nhận offer của server X" (broadcast để các server khác biết offer của họ không được chọn)
AckServerServer → clientUnicast hoặc broadcast"Xác nhận, IP là của anh"

Discover và Request là broadcast từ client. Vì client chưa có IP, nên broadcast; vì broadcast không qua router, nên cần relay (mục 4).

Các bản tin khác: NAK (server từ chối, ví dụ client xin IP không thuộc mạng này), Decline (client phát hiện IP được cấp đã có người dùng — nhờ ARP probe, tuần 2), Release (client trả IP), Inform.

✏️ Sửa so với ghi chép cũ Sổ ghi bước 2: "Server nhận thông tin (Xem xét tính xác thực (Domain), bản thân có ip để cấp không (để ý DHCP pool))". Bỏ ý "xác thực Domain": DHCP không xác thực client theo domain; server chỉ xem có pool phù hợp với mạng của client và còn IP trống không (có thể lọc theo MAC nếu cấu hình riêng). Và bước 3 sổ ghi "End device gửi DHCP request …": ghi rõ Request là broadcast.

2. Lease, gia hạn, các option hay gặp

1/ Lease

  • T1 = 50% thời gian thuê: client gửi Request unicast tới server cũ xin gia hạn (renew).
  • T2 = 87,5%: chưa gia hạn được ⇒ gửi Request broadcast tới bất kỳ server nào (rebind).
  • Hết lease mà không gia hạn được ⇒ mất IP (Windows rơi về 169.254.x.x).

2/ Option hay gặp

3. Cấu hình DHCP server trên router Cisco

R1(config)# ip dhcp excluded-address 192.168.10.1 192.168.10.20     ! không cấp dải tĩnh (gateway, máy in…)
R1(config)# ip dhcp pool VLAN10
R1(dhcp-config)# network 192.168.10.0 255.255.255.0
R1(dhcp-config)# default-router 192.168.10.1
R1(dhcp-config)# dns-server 10.1.1.53 8.8.8.8
R1(dhcp-config)# domain-name lab.local
R1(dhcp-config)# lease 1 12                                         ! 1 ngày 12 giờ (mặc định 1 ngày)
R1(config)# ip dhcp excluded-address 192.168.20.1 192.168.20.20
R1(config)# ip dhcp pool VLAN20
R1(dhcp-config)# network 192.168.20.0 255.255.255.0
R1(dhcp-config)# default-router 192.168.20.1
R1(dhcp-config)# dns-server 10.1.1.53
✏️ Sửa so với ghi chép cũ Sổ có cấu hình DHCP trên router với 3 lệnh gõ sai tên:
  • Ip dhcp exclude-address → đúng: ip dhcp excluded-address
  • Dns 8.8.8.8 → đúng: dns-server 8.8.8.8
  • Domain pedu.com → đúng: domain-name pedu.com
IOS cho gõ tắt nên "dns" có thể chạy như viết tắt của dns-server, nhưng trong sổ ghi đầy đủ để không nhầm. Và lệnh ip dhcp exclude-address 192.168.10.0 192.168.10.10: không cần loại địa chỉ network .0 (DHCP không bao giờ cấp nó).
R1# show ip dhcp binding       ! IP nào đã cấp cho MAC nào, hết hạn lúc nào
R1# show ip dhcp pool          ! số địa chỉ dùng/còn
R1# show ip dhcp conflict      ! IP phát hiện trùng (server ping trước khi cấp)
R1# clear ip dhcp binding *

Router làm DHCP client trên cổng WAN: ip address dhcp (cổng nối modem nhà mạng).

4. DHCP relay: ip helper-address

Doanh nghiệp không đặt DHCP server ở mỗi VLAN; thường có một vài server tập trung (Windows DHCP trên Domain Controller). Nhưng Discover là broadcast, không qua router ⇒ cần relay agent trên gateway của VLAN client.

DSW1(config)# interface vlan 20                      ! gateway của VLAN client
DSW1(config-if)# ip helper-address 10.1.1.67         ! IP DHCP server
DSW1(config-if)# ip helper-address 10.1.1.68         ! server thứ hai (dự phòng)

ip helper-address đặt trên interface nhận broadcast của client (gateway VLAN client: SVI hoặc sub-interface), không đặt trên interface phía server.

Relay làm gì

  1. Nhận Discover broadcast trên VLAN 20.
  2. Đổi thành unicast gửi tới 10.1.1.67, điền trường giaddr (gateway IP address) = IP của interface nhận (192.168.20.1).
  3. Server nhìn giaddr ⇒ biết client ở mạng 192.168.20.0/24 ⇒ cấp IP từ scope tương ứng.
  4. Offer/Ack quay về relay, relay chuyển xuống client.

Lưu ý: ip helper-address mặc định chuyển tiếp thêm vài dịch vụ UDP broadcast khác (TFTP, DNS, time, NetBIOS, TACACS…), không chỉ DHCP. Thiếu helper ⇒ client nhận 169.254.x.x (APIPA, tuần 3).

✏️ Sửa so với ghi chép cũ Thêm mục "DHCP relay" với lệnh ip helper-address, 4 bước trên, và câu "đặt trên interface gateway của VLAN client".

5. DNS

1/ Phân giải một tên

  1. Máy hỏi DNS server nội bộ (resolver, thường là Domain Controller) — truy vấn đệ quy (recursive): "tìm giùm tôi đến cùng".
  2. Resolver không có trong cache ⇒ hỏi lần lượt root ⇒ TLD (.vn) ⇒ authoritative của tên miền — truy vấn lặp (iterative).
  3. Trả về client, lưu cache theo TTL.

6. NTP

1/ Vì sao NTP quan trọng

  • Active Directory / Kerberos: đồng hồ client lệch server quá 5 phút (mặc định) ⇒ vé Kerberos bị từ chối ⇒ không đăng nhập domain được. Đây là câu trả lời "vì sao NTP quan trọng với AD".
  • Log: so log của firewall, switch, server khi điều tra sự cố chỉ có ý nghĩa nếu cùng giờ.
  • Chứng chỉ: lệch giờ ⇒ chứng chỉ "chưa có hiệu lực" hoặc "hết hạn".
  • Giao dịch ngân hàng: dấu thời gian là bằng chứng pháp lý.

2/ Stratum

Stratum 0: đồng hồ nguyên tử/GPS. Stratum 1: máy nối trực tiếp stratum 0. Mỗi tầng xuống +1. Stratum 16 = không đồng bộ. UDP 123.

3/ Cấu hình

R1(config)# clock timezone ICT 7 0                 ! giờ Việt Nam UTC+7
R1(config)# ntp server 10.1.1.123 prefer           ! NTP nội bộ (DC hoặc thiết bị chuyên dụng)
R1(config)# ntp server 162.159.200.1               ! dự phòng
R1(config)# ntp master 4                           ! (lab) router làm nguồn giờ stratum 4
R1# show ntp status                                ! Clock is synchronized, stratum …
R1# show ntp associations                          ! * = đang đồng bộ với server này
R1# show clock detail

Trong AD, PDC Emulator là nguồn giờ của domain; máy trạm và DC khác đồng bộ theo nó.

8. SNMP

1/ Thành phần

  • Manager (NMS): Zabbix, PRTG… hỏi và nhận tin.
  • Agent: chạy trên thiết bị (router, switch, máy in, UPS).
  • MIB: "từ điển" các thông tin có thể hỏi; mỗi mục có một OID (ví dụ 1.3.6.1.2.1.1.5.0 = sysName; ifInOctets cho lưu lượng interface).

2/ Bản tin

Bản tinHướngPort
Get / GetNext / GetBulkManager hỏi agent (poll)Tới agent UDP 161
SetManager đổi giá trị trên agent (hiếm dùng, rủi ro)UDP 161
TrapAgent chủ động báo manager khi có sự kiện (link down)Tới manager UDP 162
InformNhư trap nhưng manager phải xác nhậnUDP 162

Poll: manager → agent port 161. Trap: agent (thiết bị) → manager port 162.

3/ Phiên bản

9. QoS cơ bản

1/ Vì sao

Link nghẽn ⇒ gói phải xếp hàng ⇒ trễ, mất gói. Thoại/video nhạy cảm: thoại cần trễ một chiều < 150 ms, jitter < 30 ms, mất gói < 1%. QoS quyết định gói nào được ưu tiên khi nghẽn. Không nghẽn thì QoS gần như không làm gì.

2/ Các bước của QoS

  1. Phân loại (classification): nhận ra loại lưu lượng (theo ACL, port, NBAR nhận diện ứng dụng).
  2. Đánh dấu (marking): ghi nhãn vào gói để thiết bị sau khỏi phân loại lại. Tầng 2: CoS (3 bit trong tag 802.1Q, tuần 6). Tầng 3: DSCP (6 bit trong IP header, 0–63).
  3. Trust boundary: tin nhãn từ đâu (tuần 6 mục 10).
  4. Xếp hàng (queuing): LLQ = một hàng ưu tiên tuyệt đối (thoại) + các hàng chia băng thông theo tỉ lệ (CBWFQ).
  5. Tránh nghẽn: WRED bỏ sớm một ít gói TCP ít quan trọng trước khi hàng đầy.
  6. Policing / shaping: giới hạn tốc độ. Policing: vượt thì bỏ (hoặc hạ nhãn). Shaping: vượt thì đệm lại gửi sau (làm mượt, thêm trễ). Ví dụ: shape xuống đúng tốc độ thuê bao WAN.

3/ Giá trị DSCP cần nhớ

Lưu lượngDSCPGiá trịCoS tương ứng
Thoại (voice)EF465
Video tương tácAF41344
Tín hiệu cuộc gọiCS3243
Dữ liệu quan trọngAF21 / AF3118 / 262 / 3

AFxy: x = lớp (1–4, cao ưu tiên hơn), y = khả năng bị bỏ khi nghẽn (1–3, cao bị bỏ trước). Giá trị = 8x + 2y.

✏️ Sửa so với ghi chép cũ Tạo mục QoS: 6 bước, bảng DSCP, câu "thoại = EF 46, CoS 5". Liên hệ mục Voice VLAN cũ (đã sửa ở tuần 6 về trust boundary).

10. Lệnh kiểm tra và xử lý sự cố

Client nhận 169.254.x.x (sự cố #5 tuần này)

  1. Tầng 1–2: port up, đúng VLAN, PortFast (tuần 7), không bị port security chặn.
  2. Có DHCP Discover tới gateway không? (Wireshark, hoặc debug ip dhcp server packet trên router làm DHCP)
  3. Gateway VLAN có ip helper-address không, trỏ đúng server không? show running-config interface vlan 20
  4. Server có scope cho mạng giaddr không, còn IP không? show ip dhcp pool / DHCP console
  5. Đường giữa relay và server có thông (UDP 67/68, ACL/firewall)?

Thiết bị không lên Zabbix

  1. show snmp: SNMP chạy, có gói vào/ra?
  2. Community/user v3 khớp? ACL SNMP cho phép IP Zabbix?
  3. Firewall giữa Zabbix và thiết bị cho UDP 161 (poll) và 162 (trap)?
  4. Thử từ máy Zabbix: snmpwalk -v2c -c LabRO 10.99.0.11 1.3.6.1.2.1.1

11. Tình huống thực tế

Tình huống 1 · Cả VLAN mới nhận 169.254

Phân tích

VLAN mới tạo trên switch L3, quên ip helper-address trên SVI ⇒ Discover không tới DC ⇒ APIPA. Hoặc có helper nhưng chưa tạo scope cho mạng mới trên Windows DHCP. Checklist mở VLAN mới: VLAN + SVI + helper + scope + rule firewall + Zabbix.

Tình huống 2 · Người dùng chi nhánh không đăng nhập domain được, báo lỗi thời gian

Phân tích

Máy lệch giờ > 5 phút với DC (pin CMOS hỏng, không đồng bộ được NTP do firewall chặn UDP 123). Kerberos từ chối. Sửa giờ, kiểm w32tm /query /status, mở đường NTP.

Tình huống 3 · Zabbix không báo khi link chi nhánh down

Phân tích

Có poll SNMP (5 phút/lần) nhưng không có trap ⇒ phát hiện chậm; hoặc logging trap 4 trên router làm log LINK-5 không được gửi. Bật trap linkdown/linkup và chỉnh mức log. Kỹ sư hạ tầng luôn hỏi: "sự cố này được phát hiện bằng gì, sau bao lâu?".

Góc nhìn hệ thống DHCP, DNS, NTP là "dịch vụ nền": hỏng một cái là hàng trăm ticket cùng lúc. Syslog và SNMP là "mắt" của đội vận hành. Ở ngân hàng, chuẩn cấu hình thiết bị luôn có: NTP hai nguồn, timestamps, logging host về SIEM, SNMPv3 với ACL, trap cho các sự kiện quan trọng. Đây cũng là phần anh có thể góp ý ngay ở công ty (qua kênh phù hợp), vì anh đang dùng Zabbix/Grafana hằng ngày.

14. Câu hỏi tự kiểm tra

Trả lời ra giấy hoặc gửi cho Claude trước, rồi mới mở đáp án.

1. Bước nào trong DORA là broadcast từ client?

Discover và Request.

2. ip helper-address đặt ở interface nào?

Interface nhận broadcast của client: gateway của VLAN client (SVI/sub-interface), không phải phía server.

0–4: emergencies, alerts, critical, errors, warnings.

UDP 162, thiết bị (agent) gửi cho máy giám sát (manager).

EF (46).

Kerberos từ chối khi đồng hồ client và DC lệch quá 5 phút (mặc định) ⇒ không đăng nhập được; ngoài ra log và chứng chỉ cần giờ đúng.

Scope chứa giaddr (IP interface relay nhận Discover).
