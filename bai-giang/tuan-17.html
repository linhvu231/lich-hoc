Mục tiêu tuần này

Đầu ra trong lịch: lab hiện trên Zabbix, có ít nhất 1 trigger. Cụ thể:

  1. Cấu hình DHCP server trên router cho 2 VLAN và relay cho VLAN ở xa; đọc show ip dhcp binding.
  2. Cấu hình NTP, timestamps, Syslog về một server; chọn đúng mức logging trap.
  3. Bật SNMP (v2c trong lab, thử v3), đưa thiết bị vào Zabbix, có trigger link down.

Thứ 4 (24/02) · Lab phần 1: DHCP server trên router, relay cho VLAN khác

1,5 giờĐầu ra: thư mục W17-ip-services
PC10 (VLAN 10) ─┐ PC20 (VLAN 20) ─┴─ SW1 ── trunk ── R1 (ROAS g0/0.10 = 192.168.10.1, g0/0.20 = 192.168.20.1) ── g0/1 10.0.12.1/30 │ R2 g0/0 10.0.12.2/30 ── g0/1 192.168.30.1/24 ── SW2 ── PC30 SRV (Linux/VM) 192.168.10.200: syslog (rsyslog), Zabbix server, NTP (hoặc R1 làm ntp master) OSPF hoặc static giữa R1–R2 để 192.168.30.0/24 tới được 192.168.10.0/24

Bước 1: DHCP server trên R1 cho VLAN 10, 20

R1(config)# ip dhcp excluded-address 192.168.10.1 192.168.10.20
R1(config)# ip dhcp excluded-address 192.168.10.200
R1(config)# ip dhcp pool VLAN10
R1(dhcp-config)# network 192.168.10.0 255.255.255.0
R1(dhcp-config)# default-router 192.168.10.1
R1(dhcp-config)# dns-server 192.168.10.200
R1(dhcp-config)# domain-name lab.local
R1(config)# ip dhcp excluded-address 192.168.20.1 192.168.20.20
R1(config)# ip dhcp pool VLAN20
R1(dhcp-config)# network 192.168.20.0 255.255.255.0
R1(dhcp-config)# default-router 192.168.20.1
R1(dhcp-config)# dns-server 192.168.10.200

Bước 2: Pool cho VLAN 30 ở xa, relay trên R2

R1(config)# ip dhcp excluded-address 192.168.30.1 192.168.30.20
R1(config)# ip dhcp pool VLAN30
R1(dhcp-config)# network 192.168.30.0 255.255.255.0
R1(dhcp-config)# default-router 192.168.30.1
R1(dhcp-config)# dns-server 192.168.10.200
R2(config)# interface g0/1
R2(config-if)# ip helper-address 10.0.12.1       ! IP của R1 (DHCP server) — R2 phải có đường tới đó
Bẫy hay gặp Đặt ip helper-address ở g0/0 của R2 (phía R1) thay vì g0/1 (phía client) ⇒ không có tác dụng. Và nếu R1 không có route ngược về 192.168.30.0/24 thì Offer không quay về được relay.

Thứ 5 (25/02) · Lab phần 2: NTP, Syslog, SNMP

NTP

R1(config)# clock timezone ICT 7 0
R1(config)# ntp master 4                 ! (lab) R1 làm nguồn giờ
R2(config)# clock timezone ICT 7 0
R2(config)# ntp server 10.0.12.1
R2# show ntp associations                ! dấu * trước 10.0.12.1 (có thể mất vài phút)

Syslog

R1/R2(config)# service timestamps log datetime msec localtime show-timezone
R1/R2(config)# logging host 192.168.10.200
R1/R2(config)# logging trap notifications       ! mức 0–5: có cả interface up/down
SRV$ sudo tail -f /var/log/syslog               ! rsyslog bật nhận UDP 514 (module imudp)

SNMP

R1/R2(config)# ip access-list standard SNMP-MGR
R1/R2(config-std-nacl)# permit host 192.168.10.200
R1/R2(config)# snmp-server community LabRO ro SNMP-MGR
R1/R2(config)# snmp-server host 192.168.10.200 version 2c LabRO
R1/R2(config)# snmp-server enable traps snmp linkdown linkup

Phần A · MOP #13: đưa R1, R2 vào Zabbix bằng SNMP

# MOP-013 · Giám sát R1, R2 bằng Zabbix qua SNMP

| Mục        | Nội dung                                                         |
|------------|------------------------------------------------------------------|
| Mục tiêu   | Zabbix thu CPU, interface, uptime của R1/R2; báo khi link down    |
| Phạm vi    | R1, R2 (cấu hình SNMP), Zabbix server trên SRV                    |
| Ảnh hưởng  | Không gián đoạn dịch vụ                                           |
| Rủi ro     | Community lộ (v2c); ACL SNMP sai ⇒ Zabbix không thu được          |

## 1. Pre-check
SRV$ snmpwalk -v2c -c LabRO 10.0.12.1 1.3.6.1.2.1.1.5.0     ! trả về sysName
SRV$ snmpwalk -v2c -c LabRO 10.0.12.2 1.3.6.1.2.1.1.5.0
R1# show snmp | include packets                            ! có gói SNMP vào

## 2. Các bước trên Zabbix
1. Data collection → Hosts → Create host: tên R1, nhóm "Lab network"
2. Interfaces → SNMP: IP 10.0.12.1, port 161, SNMPv2, community {$SNMP_COMMUNITY} = LabRO
3. Templates: "Cisco IOS by SNMP" (hoặc "Network Generic Device by SNMP")
4. Lặp lại cho R2
5. (Tùy chọn) Thử SNMPv3 cho R2: securityName zabbix, authPriv, SHA + AES

## 3. Verify
- Monitoring → Latest data: có item interface Gi0/0, Gi0/1 (bits in/out), uptime, CPU
- Cột "Availability" của host: biểu tượng SNMP màu xanh
- Shut g0/1 trên R2 ⇒ trigger "Interface Gi0/1: Link down" xuất hiện trong Problems (ghi thời gian từ lúc shut tới lúc báo)
- No shut ⇒ problem tự Resolved

## 4. Rollback
- Zabbix: disable/xóa host R1, R2
- Router: no snmp-server community LabRO ; no snmp-server host 192.168.10.200

Phần B · Sự cố #5: thiếu ip helper-address, client nhận APIPA

Người khác (hoặc chính anh, viết lỗi ra giấy úp lại) gài trên R2: no ip helper-address 10.0.12.1 trên g0/1. Thêm một lỗi phụ: xóa route về 192.168.30.0/24 trên R1 (hoặc tắt OSPF network đó).

Triệu chứng người dùng: "Máy phòng 30 hiện 169.254.x.x, không vào được gì".

Gợi ý (mở sau khi làm)
  1. PC30: ipconfig 169.254.x.x ⇒ không có DHCP server trả lời. Tầng 1–2 ổn (link up, đúng VLAN).
  2. R2: show running-config interface g0/1 không có helper ⇒ thêm lại.
  3. Vẫn APIPA: debug ip dhcp server packet trên R1 thấy Discover tới (giaddr 192.168.30.1) và R1 gửi Offer, nhưng PC không nhận ⇒ R1 không có route về 192.168.30.0/24 (show ip route 192.168.30.1). Sửa route.
  4. Bài học: sửa xong lỗi thứ nhất mà triệu chứng còn ⇒ đừng nghi ngờ bản sửa, đi tiếp theo đường đi của gói (cả chiều về).

Chủ nhật (28/02) · Kiểm tra Zabbix, tự kiểm tra, tự chấm

1,5 giờĐầu ra: ảnh chụp dashboard lab (chỉ lab, không phải hệ thống công ty), 5 mức tự chấm

Câu hỏi tự kiểm tra trong lịch

1. Bước nào trong DORA là broadcast từ client?

Discover và Request.

2. ip helper-address đặt ở interface nào?

Interface gateway của VLAN client (nơi nhận broadcast).

3. logging trap 4 gửi những mức nào?

0 đến 4 (emergencies → warnings).

4. SNMP trap dùng port nào, ai gửi cho ai?

UDP 162, thiết bị (agent) gửi về máy giám sát (manager).

5. DSCP thường dùng cho thoại?

EF = 46.

6. Vì sao NTP quan trọng với AD?

Kerberos chỉ chấp nhận lệch giờ tối đa 5 phút (mặc định); lệch hơn ⇒ không đăng nhập được. Log và chứng chỉ cũng cần giờ đúng.
