1. Vì sao bỏ Telnet: SSH v2

Telnet (TCP 23) gửi mọi thứ dạng rõ, kể cả mật khẩu: ai bắt gói trên đường đi đều đọc được. SSH (TCP 22) mã hóa toàn bộ phiên. Dùng SSH v2; v1 có lỗ hổng.

Bật SSH trên Cisco cần 4 thứ

  1. Hostname khác mặc định (không phải "Router"/"Switch").
  2. Domain name (ip domain-name): hostname + domain tạo tên cho khóa RSA.
  3. Khóa RSA (crypto key generate rsa), tối thiểu 768 bit để chạy SSH v2; nên dùng 2048.
  4. User local (hoặc AAA) và line vty login local + transport input ssh.
SW1(config)# hostname SW1
SW1(config)# ip domain-name lab.local
SW1(config)# crypto key generate rsa modulus 2048
SW1(config)# ip ssh version 2
SW1(config)# username admin privilege 15 secret <mật-khẩu-mạnh>
SW1(config)# line vty 0 15
SW1(config-line)# login local
SW1(config-line)# transport input ssh          ! chỉ SSH, tắt telnet
SW1(config-line)# exec-timeout 10 0
SW1# show ip ssh                                ! SSH Enabled - version 2.0
SW1# show ssh                                   ! phiên đang mở

Switch L2 cần có IP quản trị (SVI VLAN quản trị + ip default-gateway, tuần 6) mới SSH vào được.

3. AAA: local, RADIUS, TACACS+

AAA = Authentication (anh là ai), Authorization (anh được làm gì), Accounting (anh đã làm gì, ghi lại). Ở ngân hàng, đăng nhập thiết bị đi qua server AAA tập trung (Cisco ISE, FortiAuthenticator…) với tài khoản AD, có log từng lệnh.

Tiêu chíRADIUSTACACS+
ChuẩnMở (IETF)Cisco phát triển (nay có RFC 8907)
Giao thức / portUDP 1812 (auth), 1813 (accounting)TCP 49
Mã hóaChỉ mật khẩuToàn bộ payload
Tách A-A-AGộp authentication + authorizationTách riêng 3 phần ⇒ cấp quyền từng lệnh
Dùng nhiều choTruy cập mạng: Wi-Fi 802.1X, VPNQuản trị thiết bị (admin gõ lệnh)

RADIUS: UDP, mã hóa mật khẩu, cho người dùng mạng. TACACS+: TCP 49, mã hóa toàn bộ, tách A-A-A, cho quản trị thiết bị.

AAA local (lab)

R1(config)# username admin privilege 15 secret <mật-khẩu>
R1(config)# aaa new-model                                 ! từ đây vty/console theo AAA
R1(config)# aaa authentication login default local
R1(config)# aaa authorization exec default local
! Có server thật:
R1(config)# aaa authentication login default group tacacs+ local   ! server chết ⇒ rơi về user local
Bẫy tự khóa mình Gõ aaa new-model + aaa authentication login default group tacacs+ (không có local dự phòng) khi server chưa chạy ⇒ mọi đăng nhập mới bị từ chối, kể cả console. Luôn: giữ một phiên SSH đang mở, tạo user local trước, có local ở cuối danh sách, và đặt reload in 10 trước khi thay đổi (tuần 7). Đây là sự cố của tuần này.

4. DHCP snooping

Tấn công: ai đó cắm router Wi-Fi nhà (có DHCP) vào mạng công ty ⇒ máy khác nhận IP/gateway sai (rogue DHCP); hoặc kẻ xấu cấp gateway là máy mình để nghe lén. Hay gặp thật ở helpdesk!

Cách hoạt động

  • Port trusted: cho phép bản tin từ server (Offer, Ack). Đặt trên port uplink về phía DHCP server thật (trunk lên core/distribution).
  • Port untrusted (mặc định mọi port khi bật): chỉ cho bản tin client (Discover, Request). Nhận Offer/Ack từ port untrusted ⇒ drop.
  • Switch xây bảng binding: MAC – IP – VLAN – port – lease. Bảng này DAI và IP Source Guard dùng lại.
  • Có thể giới hạn tốc độ bản tin DHCP trên port untrusted (chống cạn pool — DHCP starvation).
SW1(config)# ip dhcp snooping
SW1(config)# ip dhcp snooping vlan 10,20
SW1(config)# no ip dhcp snooping information option     ! xem ghi chú dưới
SW1(config)# interface g0/24                             ! uplink về phía DHCP server
SW1(config-if)# ip dhcp snooping trust
SW1(config)# interface range f0/1 - 22
SW1(config-if-range)# ip dhcp snooping limit rate 10
SW1# show ip dhcp snooping
SW1# show ip dhcp snooping binding

Ghi chú option 82: khi bật snooping, switch mặc định chèn option 82 vào bản tin; nếu DHCP server/relay (ví dụ router Cisco làm DHCP) không chấp nhận, client không nhận IP. Trong lab hay phải tắt bằng lệnh trên.

DHCP snooping: port trusted là port hướng về DHCP server thật (uplink).

5. Dynamic ARP Inspection (DAI)

Tấn công ARP spoofing / poisoning (tuần 2): kẻ xấu gửi ARP reply giả "IP gateway là MAC của tôi" ⇒ mọi máy gửi gói qua máy hắn (man-in-the-middle).

DAI kiểm từng gói ARP trên port untrusted: cặp IP–MAC trong ARP có khớp bảng binding DHCP snooping không? Không khớp ⇒ drop (và log). Vì vậy: DAI cần DHCP snooping chạy trước (hoặc ARP ACL cho máy IP tĩnh).

SW1(config)# ip arp inspection vlan 10,20
SW1(config)# interface g0/24
SW1(config-if)# ip arp inspection trust               ! uplink, giống snooping
SW1(config)# ip arp inspection validate src-mac dst-mac ip   ! kiểm thêm (tùy chọn)
SW1# show ip arp inspection
SW1# show ip arp inspection statistics vlan 10

Máy IP tĩnh (máy in, server) không có trong bảng binding ⇒ bị DAI chặn ARP. Xử lý: ARP ACL (arp access-list + ip arp inspection filter) hoặc static binding.

7. Wireless: bảo mật và kiến trúc WLC

1/ Bảo mật

ChuẩnGhi chú

WPATKIP, chuyển tiếp, không dùng

2/ Kiến trúc

KiểuMô tả
Autonomous APMỗi AP cấu hình riêng. Hợp nhà/văn phòng rất nhỏ

Split-MAC: AP lo việc thời gian thực (beacon, ACK), WLC lo xác thực, chính sách. Chế độ FlexConnect: chi nhánh chuyển dữ liệu tại chỗ, không kéo hết về WLC trung tâm qua WAN.

Port switch nối AP: lightweight AP local mode thường là access (VLAN quản trị AP) vì dữ liệu đi trong CAPWAP; autonomous/FlexConnect thường là trunk (mỗi SSID một VLAN).

8. SDN và controller

1/ Ba mặt phẳng (plane)

PlaneViệcVí dụ
Data (forwarding)Chuyển gói thậtTra FIB, MAC table, NAT, ACL (tuần 10)
ControlQuyết định đường điOSPF, STP, ARP
ManagementNgười/công cụ quản lý thiết bịSSH, SNMP, Syslog, API

2/ SDN

SDN (Software-Defined Networking): tập trung control plane (một phần hoặc toàn bộ) vào controller; thiết bị làm data plane.

  • Northbound API: giữa controller và ứng dụng/người quản trị (thường REST API).
  • Southbound API: giữa controller và thiết bị (OpenFlow, NETCONF, SSH/CLI, SNMP).
  • Ví dụ: Cisco Catalyst Center (DNA Center) cho campus, SD-WAN (Cisco Catalyst SD-WAN, Fortinet SD-WAN quản lý bằng FortiManager), ACI cho data center.

Mạng truyền thống: cấu hình từng hộp bằng CLI. Controller-based: khai báo ý định (intent: "VLAN khách không vào server") và controller đẩy cấu hình xuống mọi thiết bị, thống nhất, có kiểm tra.

9. REST API và mã HTTP

REST API: gọi dịch vụ qua HTTP(S). Đặc điểm: client–server, stateless (mỗi request tự mang đủ thông tin, kể cả token), tài nguyên định danh bằng URL.

12. Tình huống thực tế

Tình huống 1 · Cả phòng nhận IP 192.168.0.x lạ, không vào được hệ thống

Phân tích

Có người cắm router Wi-Fi mang từ nhà vào port mạng (cổng LAN của router có DHCP). Dấu hiệu: gateway là 192.168.0.1/192.168.1.1. Tìm port: show mac address-table theo MAC của "DHCP server" lạ (lấy từ ipconfig /all trên máy bị ảnh hưởng hoặc bảng ARP). Phòng ngừa: DHCP snooping + BPDU Guard + port security.

Tình huống 2 · Sau khi bật DAI, máy in không in được

Phân tích

Máy in đặt IP tĩnh ⇒ không có trong bảng binding ⇒ ARP của máy in bị drop. show ip arp inspection statistics thấy số drop tăng. Sửa: ARP ACL cho máy in, hoặc chuyển máy in sang DHCP reservation. Bài học: bật tính năng bảo mật L2 theo MOP, có giai đoạn thử ở một VLAN trước.

Tình huống 3 · Script gọi API trả 401 vào sáng thứ Hai

Phân tích

Token hết hạn (nhiều hệ thống cấp token 24 giờ/7 ngày). 401 = xác thực, không phải quyền (403) hay URL sai (404). Script nên kiểm mã HTTP và báo rõ, tự lấy token mới nếu có cơ chế.

Tình huống 4 · Wi-Fi tầng 3 chập chờn giờ cao điểm

Phân tích

Nhiều AP 2,4 GHz đặt kênh chồng lấn (ví dụ 3, 4, 8) hoặc quá nhiều client trên một AP. Xem trên WLC: utilization kênh, số client, RSSI. Hướng: chỉ dùng 1/6/11, đẩy client lên 5 GHz (band steering), giảm công suất cho các AP gần nhau.

Góc nhìn hệ thống Ba nhóm chủ đề tuần này nối nhau: SSH/AAA bảo vệ management plane; snooping/DAI bảo vệ tầng 2 nơi người dùng cắm vào; API/controller là cách quản lý hàng trăm thiết bị mà không gõ từng hộp. Ở môi trường ngân hàng, kiểm toán sẽ hỏi: ai đăng nhập thiết bị, bằng tài khoản gì, gõ lệnh gì (TACACS+ accounting); port người dùng có chống thiết bị lạ không.

15. Câu hỏi tự kiểm tra

Trả lời ra giấy hoặc gửi cho Claude trước, rồi mới mở đáp án.

1. Bật SSH trên Cisco cần 4 thứ gì?

Hostname khác mặc định, ip domain-name, khóa RSA (crypto key generate rsa), user local + login local trên vty (và transport input ssh).

2. RADIUS và TACACS+ khác nhau ở 2 điểm nào?

RADIUS UDP và chỉ mã hóa mật khẩu; TACACS+ TCP 49, mã hóa toàn bộ, tách riêng authentication/authorization/accounting.

3. DHCP snooping: port nào đặt trusted?

Port hướng về DHCP server thật (uplink/trunk lên core), không phải port người dùng.

4. DAI cần tính năng nào chạy trước?

DHCP snooping (bảng binding), hoặc ARP ACL cho máy tĩnh.

5. WPA3 Personal thay PSK bằng gì?

SAE (Simultaneous Authentication of Equals).

6. Mã HTTP 401 nghĩa là gì?

Unauthorized: chưa xác thực hoặc thông tin xác thực (token) sai/hết hạn.

7. Trong JSON mẫu, interfaces[0].up có giá trị gì?

true (interface Gi1/0/1).

8. service password-encryption có làm mật khẩu an toàn không?

Không: type 7 giải ngược dễ. Dùng secret (băm) cho enable và user.

9. 2,4 GHz có những kênh không chồng lấn nào?

1, 6, 11.

10. Lấy tên các interface down trong JSON mẫu bằng jq?

jq -r '.interfaces[] | select(.up==false) | .name' ⇒ Gi1/0/2.
